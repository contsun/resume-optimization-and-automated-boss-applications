# Resume Optimization and Automated BOSS Applications

从一份现有简历开始，自选「优化后找工作」或「直接匹配岗位」；没有简历则从真实材料生成。各路线最终汇合到 BOSS 直聘投递前确认与结果核验，可选接入经明确授权的定时首次沟通模块。

**版本：0.2.0，开源预览版（Preview），供配置试用，不是稳定版。** 面向有真实工作、项目或实习经历的求职者，不限定行业、年限、城市或薪资；优化简历不是匹配岗位的强制步骤。

> 当前浏览器适配器面向 macOS Google Chrome，尚未完成真实在线投递验收。默认关闭真实发送；首次须配置自己的账号、求职条件与浏览器，并明确授权。请先运行零发送演示，不要把离线测试通过理解为现行平台已验证可用。

## 项目边界

- 提供方法、空白模板、明确标注的虚构案例、Python 离线工具和可选自动化模块。
- 不包含任何真实候选人的简历、公司履历、联系方式、聊天记录或浏览器数据。
- 默认不连接平台、不点击、不发送；可选自动化仅在本人完成登录、配置条件并明确授权后执行首次招呼，不发送附件、不修改简历、不代登录或处理验证码。
- 不承诺录用、回复率、绕过平台限制或所谓「安全投递频率」。
- 在线简历保存、首次招呼、附件送达、招聘方回复和面试是不同事件，分别核验。

**本项目默认所称 BOSS「投递」是筛选后点击「立即沟通」并核验首次招呼，不包含发送附件简历文件。** 在线或附件版本与参考简历不同，仅作提示，由用户决定是否更新；不是继续首次沟通的阻断条件。另行上传、更新或发送文件仍需确认。

## 先看整个使用流程

```text
开始：有现成简历吗？
├─ 有 → 提供简历，确认版本 → 想先优化，还是直接匹配岗位？
│   ├─ 先优化 → 按需补充材料 → 完善简历 → 本人确认定稿
│   └─ 直接匹配 → 保留原文 → 确认这次使用的原简历
└─ 没有 → 述职/项目等获授权材料，或口述经历 → 生成并完善 → 本人确认
                ↓ 三条路线汇合
确认求职条件 → 可以只匹配、不发送；决定投递再进入以下步骤
本人在自己的电脑浏览器登录 BOSS → 确认当前账号与执行能力
选择：只更新在线简历 / 只更新附件简历 / 两者都更新 / 都不更新
选择更新则先看差异、确认修改，再核验保存和版本；不更新则保留原状
确认本次岗位范围、数量与允许的发送动作 → 本人操作 → 核验并记录
```

**不用先安装项目、填完表格或准备齐全部材料。** 将公开的 [入门提示词](prompts/resume-intake.md) 和自己的简历交给信任的助手；无简历时直接说明，让助手引导准备获授权的述职摘要、项目说明或口述经历。可同时提供目标 JD，但 JD 不是第四条独立路线。

可以直接这样开场：

- 有简历：「这是我的简历，请按本项目流程先确认版本，再让我选择先优化还是直接匹配岗位，暂不修改平台资料或投递。」
- 无简历：「我没有简历，请先告诉我可以准备哪些述职或项目摘要；没有的部分通过访谈整理，再生成并完善简历。」

每一步都告诉用户「已完成什么、还差什么、下一步需要选择什么」。详见 [完整入门路线](docs/00-start-here.md)、[BOSS 投递前确认](docs/02-boss-application.md) 和 [完整对话示例](docs/06-walkthroughs.md)。

进入岗位筛选时，用 [投递条件卡](templates/application-preferences.md) 先确认「投什么岗位、哪些城市、薪资要求」，再按需补充行业、工作方式、排除项、硬条件/可协商项和本次最多沟通数量。不默认继承简历中的地点、薪资或任何案例偏好。

**能力说明：提供教程、提示词、模板、离线工具，以及可配置调度、筛选、去重、单次首次沟通与回执核验模块；不是带界面的应用。** 内置浏览器适配器目前仅面向 macOS Google Chrome；本人负责登录、资料更新和平台规则确认。新适配器尚未做真实在线发送验收，不能宣称所有客户端均可用或一键投递已验证。

本项目不是简历上传网站，也不会把使用者的材料自动发送给项目作者。简历离线工具不联网；可选自动化通过本人授权的浏览器访问平台，可选通知调用本人配置的通道。你选择的 AI 助手也可能通过模型服务处理输入；使用前确认接收方和数据流，不默认等于全离线。

## 可选：建立本地私有工作区

要求 Python 3.10 或更高版本，仅使用标准库，无须安装依赖或配置密钥。

```sh
python3 scripts/workflow.py init my-search
```

1. 从旧简历或 `private/my-search/intake.md` 开始，在 `session-plan.md` 记录选择的路线与确认进度；不要求先填表。
2. 选择优化或生成时，按 [简历优化教程](docs/01-resume-optimization.md) 整理事实与正文；选择直接匹配则不改写原简历。
3. 用 `application-preferences.md` 对话确认投递条件，再记录到 `profile.json`；单独保存配置不会操作平台。事实底稿由助手或本人按需整理。
4. 按 [BOSS 投递教程](docs/02-boss-application.md) 完成浏览器本人登录、简历更新选择和本次投递确认，再自行操作。
5. 在 `private/my-search/applications.csv` 记录结果，运行本地去重与统计：

```sh
python3 scripts/workflow.py dedupe private/my-search/applications.csv
python3 scripts/workflow.py summary private/my-search/applications.csv
```

这两个命令只读取本地 CSV，不查询平台。输出依据人工记录，不独立证明平台已送达。去重发现疑点时返回非零退出码，供人工核验，不自动决定可以发送。

## 可选：可配置的定时首次沟通

初始化同时生成 `private/my-search/automation.json`，默认 `enabled=false`、`dry_run=true`。已有个人任务中的基础标准现为可修改配置，不再绑定作者的账号、条件、路径或机器人：

| 配置 | 默认值 |
| --- | --- |
| 启动窗口 | 每天上午 09:30–11:30、下午 14:30–16:00，各随机启动一批 |
| 数量 | 每批最多尝试 50 次，每天合计最多 100 次 |
| 间隔与时限 | 尝试之间至少 31 秒，单批最长 130 分钟，午夜停止 |

这些数值可改，不是保证成功数或平台安全频率。**首次仍需配置自己的账号、求职条件、浏览器窗口和页签，并确认有截止日期的授权；之后调整时间与数量无需改脚本，但须重新确认受影响授权。**

```sh
python3 scripts/automation.py demo
python3 scripts/automation.py validate private/my-search
python3 scripts/automation.py plan private/my-search
```

演示完全使用虚构数据，不读取浏览器、不发送。真实启用、持续调度、暂停、人工核验、历史去重和可选通知见 [自动化配置教程](docs/07-automation.md)。不自动安装系统任务，也不修改原有任务。

## 公开前检查

```sh
python3 -m unittest discover -s tests -v
python3 scripts/release.py
python3 scripts/release.py --export exports/resume-optimization-and-automated-boss-applications-0.2.0.zip
```

导出器只打包 `config/public-files.json` 中的文本文件，拒绝未知文件、敏感特征及符号链接，不打包 `private/`、`exports/` 或 `.git/`。检测不等于完全匿名；还须人工审核上下文、贡献者信息和发布页面。

**不要把自己的工作目录直接推送到公开仓库。** 将检查通过的导出包解压到全新空目录，人工复核后再初始化公开仓库；不要复制旧 Git 历史。项目生成的真实求职资料保存在本机私有目录，不等于所选聊天或模型服务也完全在本机处理数据。详细步骤见 [隐私与发布](docs/03-privacy-and-release.md)。
