# 第一次使用：三条路线，一个投递前入口

**有简历就先提供简历，再选择要不要优化；没有简历才进入从材料生成的分支。** 无需先安装工具或填完问卷。本项目提供方法与模板，不提供集中收集简历的网站、聊天账号或托管服务；需要定时首次沟通时，另按 [可选自动化模块](07-automation.md) 配置与授权，不因开始整理简历就自动启用。

## 第一步：接收现有简历，或选择没有简历

将简历以自己选择的助手当前可读取的附件或文字形式提供给它，并使用 [入门提示词](../prompts/resume-intake.md)。如果助手无法访问仓库，需要一并提供提示词与相关公开模板，不要只给它一个无法访问的本机路径。

有简历时先确认当前文件能否读取、是否为本次要用的版本，简要读回主要经历，不默认开始改写。文件无法读取时说明实际情况，改请用户补文字或使用获授权的本地转换工具；不假装已经分析。

随后明确询问：

> 这次您想先优化这份简历，还是保留原文、直接按它寻找匹配岗位？也可以暂时只分析，不进入投递。

如果用户明确说没有简历，进入路线 C，不要求先上传一个文件才能继续。用户不知道方向也可以先整理经历，但不从履历擅自推断薪资、城市或必须接受的条件。

## 路线 A：有简历，先优化

1. 用户选择优化后，再给出定位、结构、表达和事实缺口诊断。
2. 建议按需提供获授权的年终述职/绩效总结摘要、项目复盘、作品说明或口述；没有材料也能访谈补充。
3. 将事实分成原文陈述、本人确认、待核实，每轮只问 3～5 个关键问题；个人贡献、团队贡献和成果口径分开。
4. 输出正文草稿、修改说明与待确认项，不覆盖原文件，不编造事实。
5. 本人确认后确定本次使用的版本；只有明确同意进入求职/投递准备，才汇合到下方共用入口。优化完成不自动开始发送。

详细方法见 [优化与生成教程](01-resume-optimization.md)。

## 路线 B：有简历，不优化，直接匹配

- 原文保持不变，确认本次使用的文件与版本，不强制生成优化稿或填写完整事实台账。
- 可以提取履历能力用于解释匹配依据，但不能顺便改写简历或更新平台资料。
- 仅补齐岗位匹配需要的方向、地点、薪资周期与硬限制；有目标 JD 可补充，没有也可先讨论条件。
- 如果发现影响匹配的事实冲突、必要信息缺失或误传旧文件，提出具体问题；不优化不等于忽略明显矛盾。
- 用户可只看匹配建议，不进入平台发送；选择投递后才进入共用入口。

## 路线 C：没有简历，从真实材料生成

生成和优化共用同一套事实整理方法，区别只是起步时没有现成正文。先从 [简短信息卡](../templates/intake.md) 任选能回答的问题：最近做过什么、本人负责什么、最值得介绍的一两件事，以及想找什么工作。

建议提供获授权的年终述职摘要、季度总结、项目介绍/复盘、作品说明、历史自我介绍等；**这是可选素材，不是必须提交的文件清单**。优先摘要和代号，不索要保密原件、客户名单、合同或后台原始数据。没有这些材料时通过口述继续。

逐段补充时间线、角色、动作、成果、教育与必要资质，输出第一版正文，再按路线 A 的方法完善。没有可信数字就写真实的定性结果。本人确认事实和版本后再进入求职准备，不能直接把未确认的生成稿上传或投递。

## 三路汇合：BOSS 投递前的共用入口

按 [投递前教程](02-boss-application.md) 逐步走，不要求用户一次完成所有选择：

1. 用 [投递条件卡](../templates/application-preferences.md) 确认参考简历、目标岗位、城市、薪资范围与匹配口径，再补充硬条件、偏好、排除项和本次最多沟通数量；确认只是匹配，还是准备首次沟通。
2. 明确告知：「需要您本人在自己的电脑浏览器打开 BOSS 直聘并完成登录，完成后告诉我；不要发送密码、验证码或 Cookie。」
3. 用户确认登录后核对本人账号与当前页面；只有实际具备页面读取能力的工具才能声明已经核验，否则由本人确认，不假装看到浏览器。
4. 展示在线简历与附件简历的独立选择：只更新在线、只更新附件、都更新、都不更新。默认均不修改。
5. 选择更新时，先确认目标版本、差异与允许的修改范围，再由本人操作并核验；选择不更新则保留原状。仅版本不同或未核对时轻提示一次，由用户决定，不把一致性作为首次沟通前提。
6. 预览匹配依据和排除原因，确认本次范围、数量与发送动作。默认投递只点「立即沟通」并核验首次招呼，不发送附件文件；登录和更新均不构成发送许可。
7. 本人开始操作，分开核验首次招呼、附件、回复；未知结果先暂停，不重复点击。

只匹配用户提供的 JD，不需要为了离线分析先登录。需要查看平台页面时，以实际入口是否要求登录为准。默认由本人完成平台操作；可选自动化只在另行配置和明确授权后执行首次招呼，不上传或更新资料。

## 信息准备清单：按需要补，而非一次全部提交

| 信息 | 何时需要 | 不知道或不方便提供时 |
| --- | --- | --- |
| 旧简历或工作/项目经历 | 起步材料，二选一 | 可以口述，助手逐步整理 |
| 想找的岗位或方向 | 有则起步时说明 | 先梳理经历，再讨论定位 |
| 城市、工作方式、薪资期望 | 定位与岗位筛选时 | 可以暂不填写，不影响初读 |
| 雇主/品牌、真实角色与年月 | 经历定稿前 | 首轮可用代号，准确事实只在私有材料中确认 |
| 个人动作、决策边界与合作关系 | 成果改写时 | 用具体事例追问，不把团队成果全算给个人 |
| 数字、口径、时间窗口和来源 | 使用数字前 | 保留待确认或改用真实的定性描述 |
| 教育、实习及必要资质 | 相关章节定稿前 | 本人确认文字即可，不默认收集证件扫描件 |
| 年终述职/绩效总结、项目复盘、作品、过往反馈 | 生成/优化时可选补充 | 提供获授权的摘要；没有则口述，不是启动门槛 |
| 目标 JD | 岗位专属适配时可选 | 没有也能先做通用诊断 |

姓名、电话、个人邮箱、精确住址、证件、工资流水、合同和后台原始数据都不是初次优化的必交材料。优先使用占位符；涉及第三方的材料只给必要且允许分享的摘要。

## 项目怎样参与，而不是材料发给谁

- 可以先在自己信任的助手会话中开始，项目不是使用该助手前必须完成的注册或申请步骤。
- 其他使用者把材料交给自己选择并信任的助手，不会自动发送给本项目作者；公开仓库、Issue 和 PR 都不是提交真实简历的入口。
- 聊天附件已经交给所选聊天/模型服务处理，不能仅因项目有离线脚本就宣称输入从未离开本机。
- 需要本地归档时，再运行 `python3 scripts/workflow.py init my-search`，将本人材料和助手整理结果放入 `private/my-search/`。没有本地写文件能力的助手可以先输出正文，由本人私下保存。
- 本项目没有通用附件解析、OCR、云端接收或自动生成最终 PDF 的实现；文件读取与转换能力取决于实际使用的助手和本地工具，不支持时退回文字输入。
- 优化简历不构成把简历发给招聘方的授权；资料上传、对外沟通和附件发送是后续独立动作。
- 可在 `private/my-search/session-plan.md` 记录路线、当前步骤、版本和确认结果；它是人工检查表，不是自动授权或执行状态机。

## 每一步都让用户知道下一步

有简历的第一轮应读回版本并提供路线选择，而不是直接改写或投递；没有简历的第一轮应提供材料建议和少量访谈问题。后续每步都说明「已完成、待确认、下一步」，允许暂停、改路线或只读分析。

暂停后只恢复已确认事实，不自动复用发送授权；更换简历版本后重新核对相关预览和上传选择。对话示例见 [从开始到投递的三种走法](06-walkthroughs.md)。

仅平台与参考简历版本不同，不撤销已确认范围内的首次沟通；真正新增上传/发送文件或修改硬条件时，才另行确认受影响动作。默认首次招呼与附件文件发送始终分开记录。
