# 简历优化教程

这份教程帮你把做过的事写清楚，让招聘方看懂你的经历和能力。已有简历可以直接改，没有简历也可以从一段工作或项目经历开始。

整个过程不需要安装脚本：使用项目提供的提示词和模板，配合你常用的 AI 助手整理，最后把正文放进自己的文档中排版。

## 先从这里开始

| 你的情况 | 怎么开始 |
| --- | --- |
| 已有简历，想改得更清楚 | 提供这次要修改的版本，说明目标岗位和最想解决的问题 |
| 没有简历，不知道怎么写 | 先填 [个人信息模板](../templates/intake.md) 中知道的部分，或直接口述最近的经历 |
| 还没决定找什么工作 | 先整理经历，再和助手一起讨论适合的方向 |
| 不想改简历，只想看岗位 | 保留原文，说明求职条件即可，不必先完成本教程 |

可以直接复制 [简历整理提示词](../prompts/resume-intake.md)，再加上自己的材料。下面按实际整理顺序介绍具体怎么做。

## 第一步：准备手头已有的材料

最简单的起点就是一份旧简历。没有旧简历时，先用自己的话说清楚三件事：

1. 最近在哪里工作、学习或实习，大概做了多久？
2. 平时主要负责什么，亲自做过哪些事？
3. 最值得介绍的一两个项目或成果是什么？

有工作总结、项目复盘或作品说明时，可以挑相关内容补充，不用一次整理齐全。只提供自己能分享的摘要；公司名和项目名可以先用代号，不必上传内部原件、客户名单或合同。

如果助手读不到附件，就把需要处理的内容粘贴成文字。姓名、电话和邮箱可以等定稿时再补，不影响先改正文。

## 第二步：先想清楚这份简历给谁看

先选一个主要方向，再决定哪些经历值得展开。你可以这样告诉助手：

> 我想找产品经理岗位。请从我提供的经历中，找出与需求分析、项目推进相关的内容；如果不清楚我具体负责了什么，先问我。

如果还没有目标岗位，可以先问：「从这些经历看，我有哪些比较突出的能力，适合继续了解哪些工作？」不用急着给自己定一个职位名称。

城市、薪资和工作方式可以先记为求职条件，不必全部写进简历。面向不同方向时可以另存不同版本，但公司、时间、职位和成果等事实应保持一致。

## 第三步：把经历写具体，而不是只换几个词

一条经历至少要让人看懂：**你做了什么、怎么做的、最后完成了什么。**

不容易下笔时，用下面的问题回忆：

- 当时有什么问题，为什么要做这件事？
- 你本人负责哪一部分，和谁一起完成？
- 你具体做了哪些动作或决定？
- 最后交付了什么，带来了什么变化？
- 如果有数据，它来自哪个时间段，统计的是什么？

不需要每一条都写成五段，也不用每句话都带数字。先把事情讲明白，再压缩成适合简历的长度。

### 看一个改写例子

**以下为虚构示例，只演示写法，不要直接当作自己的经历使用。**

原句：

> 负责工单系统，赋能团队协作，提升处理效率。

不补造数据，也可以写具体：

> 针对跨团队工单交接不清的问题，整理处理流程，制定统一的状态和分派规则，并推动试点上线，让处理人和交接进度可以在同一页面查看。

如果确实有统计数据，可以补充结果：

> 在试点团队连续观察 4 周，按相同口径统计，工单平均处理时长由 12 分钟降至 9 分钟。

重点不在于写得更夸张，而在于把含糊的「负责」「提升」换成具体的做法和结果。团队完成的项目要写清自己的部分，参与过不等于独立负责，更不等于主导。

做过技术、AI 或其他个人作品时，也按这个思路写：解决什么问题、自己做了什么、实际完成到哪一步。课程练习、原型、试用和正式上线要区分，不用为了显得完整而写成上线项目。

## 第四步：把内容排成好读的简历

可以从下面的结构开始，再按自己的经历增减栏目：

| 栏目 | 写什么 |
| --- | --- |
| 基本信息 | 姓名、必要的联系方式、目标岗位；在自己的定稿中补齐 |
| 简短介绍 | 用几句话说明经验、擅长的工作和最相关的成果；没有合适内容可以省略 |
| 工作或实习经历 | 按时间从近到远，写清公司、职位、起止时间和具体贡献 |
| 项目或作品 | 展开一两个相关案例；工作经历里已经讲清楚的内容不用再重复 |
| 教育经历 | 学校、专业、学历、就读时间；在读就写在读 |
| 技能与证书 | 只写实际会用、与岗位相关的内容，最好能对应到经历 |

最近、最相关的经历多写一些，早期或重复内容适当压缩。应届生可以把教育、实习和项目放在更前面，不必为了凑栏目而填空话。

可以先尝试控制在 1～2 页，经历较多时以信息清楚为先。不要为了压页数把字号缩得很小，也不要用大段自我评价占位置。

需要空白正文格式时，可以参考 [简历正文模板](../templates/resume.md)。

## 第五步：按目标岗位调整重点

有感兴趣的职位描述时，重点看它希望你做什么，再找出自己真正做过的相关事情：

1. 把相关经历放到更容易看到的位置，补上能说明能力的具体例子。
2. 用招聘方看得懂的说法解释内部项目名和缩写，删掉无关的术语。
3. 没做过的内容就保留为差距，不要为了匹配关键词添加经历、学历或技能。

例如，岗位更看重跨部门推进，就突出你如何协调需求、处理分歧和推动交付；更看重数据分析，就说明分析对象、使用方法和分析如何影响了后续工作。两种写法都应来自你实际做过的事。

想逐项对照职位要求，可以使用 [岗位分析模板](../templates/jd-review.md)；没有具体职位时，先保留通用版即可。

## 第六步：让助手把结果整理成这三部分

不要只拿到一份长篇诊断，再自己拼出简历。材料足够后，可以直接要求：

> 请先给我可以复制使用的简历正文，再用不超过 5 条说明主要改动。还有需要补充的信息时，最后列出几个具体问题。点评不要夹在正文里。

建议按下面的顺序接收结果：

### 一、简历正文

这是可以复制进文档的部分。草稿缺少的信息用 `[待补充：起止月份]` 这样的标记，不要让助手猜；定稿时把标记补好，或者删去无法确认的内容。

### 二、这次改了什么

说明保留了哪些重点、压缩了哪些内容、为什么调整顺序。从零写简历时，说明内容是怎样组织起来的即可，不用逐句解释。

### 三、还需要我补充什么

只留下影响下一版的问题，每轮最多 3～5 个；没有问题就省略，不必重复一遍已知经历。

## 第七步：保存成自己的投递版本

保留原文件，把修改稿另存为新版本。将正文复制到 Word、WPS 或自己常用的编辑器中排版，需要附件时再导出 PDF。

发出去前，花几分钟检查：

- 公司、职位、日期、学历和在职状态是否准确；有数字的地方能否说明它代表什么。
- 姓名和联系方式是否正确，有没有遗留的 `[待补充]`、修改说明或编辑批注。
- PDF 的分页、字号是否好读，文字是否可以选中、复制，作品链接是否能打开。
- 有没有把公司内部信息、私有编辑记录或不准备公开的材料放进正文。

这些文件保存在自己的文档目录，或项目的 `private/` 中，不要提交到公开仓库。

## 常见问题

**没有成果数字，是不是就没东西可写？**

不是。可以写清交付了什么、服务了哪些人、流程有什么变化。只写自己知道的结果，不需要把每一条经历都包装成百分比增长。

**助手写得还是很像 AI，怎么改？**

让它保留事实，删除套话，换成你能在面试中自然讲出来的句子。拿不准时就追问：「这句话具体指哪件事？我做了什么？」如果答不出来，就补充事实或删掉这句。

**有些材料不方便给助手，怎么办？**

用公司或项目代号，自己概括能分享的部分即可。你选择的 AI 服务会处理输入内容，因此不要把保密原件或不需要的个人信息直接发过去。

**一定要优化完才能投递吗？**

不需要。可以继续使用现有简历。准备好求职条件后，按 [BOSS 投递操作说明](02-boss-application.md) 操作，或在 [项目首页](../README.md) 配置自动投递；整理简历本身不会开启投递。
