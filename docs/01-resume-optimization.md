# 如何从材料生成、优化并完善简历

目标不是润色成更夸张的履历，而是让招聘方更快看懂：你解决什么问题、实际负责什么、取得什么结果，以及这些内容能否被核实。

**第一次使用先看 [从哪里开始](00-start-here.md)。已有简历先选择是否优化，选择直接匹配则跳过本教程；没有简历则从真实材料生成并完善。下面的事实底稿是整理过程，不是要求用户提前填完的入场条件。**

## 0. 按所选路线准备素材

已有简历并选择优化：以用户提供的版本为起点，先说明需要补足什么，不覆盖原稿。无简历：以经历概况和获授权素材为起点，生成初稿后继续同一套优化方法。

可建议用户准备以下任一类素材，无需全部具备：

| 素材 | 主要补充什么 | 提供方式 |
| --- | --- | --- |
| 年终述职、季度或绩效总结 | 职责范围、阶段目标、成果和个人贡献 | 提供获授权摘要或脱敏片段，不索要保密原件 |
| 项目介绍、复盘或产品说明 | 背景、决策、交付边界、结果与教训 | 隐去内部系统、客户及敏感经营数据 |
| 作品、演示、自我介绍 | 具体做过什么及可展示成果 | 仅提供本人有权分享的内容 |
| 口述经历 | 没有现成材料时建立事实底稿 | 分轮追问，未知保留待确认 |

从总结里提炼成果，不把团队或公司总成绩自动归为个人，也不把内部敏感数据直接复制到对外简历。没有素材不阻塞开始，没有证据不生成貌似真实的数字。

## 1. 先建立事实底稿

原简历和已获授权的证明材料保留在私有目录，不直接覆盖。先从用户提供的简历或口述中提取信息，再由助手或本人用 `facts.csv` 登记每项经历：

- 雇主主体与业务品牌、真实职位、准确起止月份、在职状态。
- 个人决策范围、直接管理与跨部门协作的区别。
- 项目背景、关键动作、交付范围、结果及证据来源。
- 数字的时间范围、基数、单位、归属、统计方式和本人确认状态。
- 公开权限：可公开、需概括、仅面试可谈或不可披露。

证据引用用本地编号，不将内部截图或文档原文放进公开仓库。没有证据时保留「待确认」，不能让 AI 自动补齐。

## 2. 选择一个主定位

先明确目标角色、职级、城市、薪资可谈范围和硬限制，再阅读少量有代表性的真实 JD。区分：

| 类型 | 处理方式 |
| --- | --- |
| 硬性条件 | 地点、必要资质、工作方式等，明确是否满足 |
| 核心职责 | 找到自己能证明的相关经历 |
| 加分项 | 缺少时不冒充具备，可以解释迁移能力 |
| 信息缺口 | 待问招聘方，不擅自推断 |

输出一句定位：「目标角色 + 核心业务领域 + 最有证据的能力」。不同方向可有不同简历版本，但共享同一事实底稿。

## 3. 调整阅读结构

推荐顺序：必要联系信息 → 求职定位 → 简短职业概述 → 核心能力 → 倒序工作经历 → 代表项目 → 教育与必要资质。

- 概述用约 3～5 行表达经验、业务复杂度和代表结果，删去无法证明的自我评价。
- 最近、最相关经历优先展开；早期或重复经历压缩，不遗漏关键时间线。
- 每段经历写清角色和贡献，不堆砌技术名词或通用职责。
- 工作经历与项目不要机械重复；项目展开最值得被追问的案例。
- 页数按经历决定，通常先尝试 1～2 页；不为压页数牺牲可读性，也不宣称固定页数能通过所有筛选系统。

## 4. 将职责改成可验证成果

每条采用「业务问题 → 个人动作/决策 → 交付范围 → 结果 → 口径」。

**虚构教学例子，不可直接当作自己的经历：**

- 原句：负责工单系统，提高处理效率。
- 改写：针对跨团队工单交接问题，定义统一状态和分派规则，组织试点上线；在同一试点范围与统计方式下，处理时长由 12 分钟降至 9 分钟，观察期为 4 周。

没有可信结果数字时，可以写交付范围、流程变化、覆盖角色和验证方法；不能从「做了功能」推导出收入增长。公司级收入不直接归为个人业绩，百分点变化不能误写成增长百分比。

AI 项目需分清真实上线、试点、个人原型和学习练习；描述用户场景、数据/模型选择、评估方法、失败边界、成本与业务结果，而不是仅列模型名称。

## 5. 针对岗位适配，不改事实

用 `jd-review.md` 对照 JD：优先呈现最相关事实、补充招聘方能理解的术语、压缩无关内容，记录尚缺的证据。不要为关键词匹配编造行业经验、年限、学历或管理规模。

可选提示词在 `prompts/`。只向已获授权的模型提供最小必要信息；默认先以占位符替换姓名、联系方式、雇主、内部系统和敏感指标。模型建议必须由本人复核。

## 6. 发布给招聘方前自检

- 日期、年限、公司/品牌关系、职位、在职状态一致。
- 每个数字能回答「什么口径、哪段时间、你的贡献、证据在哪」。
- 文件名与正文版本一致；在线简历、PDF 和自我介绍没有事实冲突。
- 本地导出 PDF 后检查分页、字体、可选中/检索文字、手机阅读与联系方式；避免整份简历只有图片。
- 排查批注、修订、隐藏文字、链接、二维码、文档属性及多余个人信息。
- 保留经本人确认的主版本和修改记录；针对不同岗位记录使用的版本。

本版本不内置 PDF、Word 或 H5 渲染器。可通过自己选择的本地编辑器完成导出，产物仅保存到 `private/`，不要混入公开包。

## 7. 持续完善

根据具体拒绝理由、面试追问和岗位适配问题迭代，不根据极少量反馈下结论。每次只记录清楚改了什么、对应哪个岗位、后续结果如何；回复率不能只归因于简历，更不能承诺改完一定获得面试。
