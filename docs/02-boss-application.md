# BOSS 投递前：本人登录、选择简历更新、确认本次投递

适用于原简历直接匹配、优化后匹配、从零生成后匹配三条路线。默认使用人工流程、提示词和核验模板；需要定时首次沟通时，另按 [自动化配置教程](07-automation.md) 配置并明确授权。按钮、审核、附件能力及显示文案会变化，应以使用时官方客户端、账号状态和协议为准。

**这里的默认「投递」仅指点击「立即沟通」并核验同一岗位的首次招呼，不是发送附件简历文件。** 更新在线资料、上传/替换附件、在会话中发附件都是另外的动作，不默认包含。

## 1. 确认路线、版本与求职目标

确认用户选择的路线、实际使用的文件和版本。直接匹配路线不要求重写；优化/生成路线必须先经本人确认正文，不使用未确认草稿。

岗位、城市、薪资周期、硬限制和排除条件由本人确认，不从历史案例继承。可以只匹配用户提供的 JD、不登录、不修改、不发送；决定使用平台并准备沟通时才进入后续确认。给出材料不等于允许上传或发送。

## 2. 提醒用户本人登录电脑浏览器

必须在平台操作前明确提示：

> 接下来需要您本人在自己的电脑浏览器打开 BOSS 直聘，登录自己的账号。完成后告诉我「已登录」。不要把密码、验证码、Cookie 或浏览器登录数据发给我。登录本身不会授权修改简历或开始投递。

用户未登录就停在此步，不借用其他账号，不自动找历史登录态。出现验证时由本人处理，不绕过。

登录后，由本人核对账号和当前页面。如果所用助手实际具有获授权的可见页面读取能力，可以再只读核对，并说明核验依据；没有该能力时直说，不能仅凭一句「已登录」就宣称已经看见浏览器。登录不会自动赋予普通聊天助手浏览器控制能力；可选 Chrome 适配器仍需本人配置页面、检查权限并单独授权。

## 3. 在线简历与附件简历分别选择

根据本次简历，说明准备同步到在线字段和附件文件的内容，由用户选择：

| 选择 | 允许的动作 | 必须保持不变 |
| --- | --- | --- |
| 只更新在线简历 | 本人确认的在线字段修改 | 现有附件 |
| 只更新附件简历 | 本人确认的目标附件上传或替换 | 在线正文 |
| 两者都更新 | 两项分别预览、确认与核验 | 未授权字段、隐私与其他设置 |
| 都不更新 | 不保存、不上传，保留原状 | 全部平台资料 |

默认不改，不把「这份简历已确认」当作「同意同步到平台」。不合并授权，不为保持一致而顺手修改另一处。

选择更新时：

1. 对照 [资料核对表](../templates/boss-profile.md)，展示拟修改字段、主要差异、目标文件名与版本。
2. 本人确认修改范围后再操作；需要替换或删除旧附件时另外明确，不静默删除历史文件。
3. 按当前页面支持的入口由本人保存或上传；格式、大小和审核限制以页面为准，不承诺未核验的规则。
4. 操作后预览与读回，核对姓名、职位、年月、联系方式、正文、文件名和版本；分别记录保存、审核和附件可用状态。
5. 不将内部事实底稿、述职原件、项目证据或其他隐私材料当成简历上传。

选择不更新时保留原状。若已知平台与本地参考稿不同，或尚未核对版本，只轻提示一次：「平台仍保留现有资料，是否更新由您决定；不更新也可以继续首次沟通。」不强制比对一致，不因仅有版本差异或未知而阻断已确认范围内的首次沟通，也不谎称版本一致。

不发送附件不代表在线资料必然不可见；官方使用帮助将主动发起沟通列为隐藏简历时的可见性例外。仅作一次提示，是否更新仍由用户选择，实际以账号设置和当前页面为准；来源见 [官方资料入口](05-sources-and-limitations.md)。

保存成功不等于审核通过或首次沟通成功。更新失败、审核或附件状态不明确时如实报告；除非用户明确要求「更新完成后再沟通」，这些不是仅发首次招呼的必停条件。实际上传或发送附件时才需确认具体文件、版本和对象，不自动改用其他文件发送。

## 4. 明确筛选条件并展示匹配依据

使用 [投递条件卡](../templates/application-preferences.md) 逐步询问，由助手整理，不要求用户预先填表。先确认三项：

| 必问主题 | 让用户说明什么 |
| --- | --- |
| 目标岗位 | 职位名称/方向、是否接受相近岗位；职级按需补充 |
| 城市与工作方式 | 哪些城市及优先级，是否接受远程、混合或异地 |
| 薪资要求 | 币种、月薪/年包、税前/税后、最低要求和期望范围；范围有交集即可还是要求起薪达到最低值 |

随后按需补充行业或公司偏好、排除岗位/公司、学历/经验等条件的严格程度、可协商项，以及本次最多新增沟通数量。岗位、城市、薪资可以由用户明确选择「不限」或「面议另议」；未知则先讨论，不擅自当作没有限制。

把硬门槛与优先项分开，读回条件后请用户确认；不从简历、案例或历史批次继承个人偏好。仅补缺项，已说清的不重复问。实际岗位的学历、经验与其他要求仍需核对；可讨论的缺口如实标注，不为了匹配而编造经历。

薪资须先统一单位和周期：月薪、年包、计薪月数、奖金及股权不能混算。范围有交集只表示可进一步确认，不代表能拿到期望薪资；面议或信息不全标为待确认。以实际详情而非搜索卡片摘要作判断。

`profile.json` 的字段只记录这些已确认偏好，不是已实现的自动筛选引擎。`salary.matching_rule` 可记录 `range_overlap`、`posted_minimum_at_least` 或 `manual_review`；未知保留空值，不能由助手擅自放宽。

切换推荐标签、搜索条件或页面后重新核对地点及实际职责，不假定筛选条件一直保持。不会为了完成固定数量放宽硬条件。

## 5. 检查历史与实际空缺

发送前检查全部人工台账，而不只是当天或当前平台：

- 同一平台、同一岗位标识：避免重复沟通。
- 同一雇主、同一招聘方：复核是否已建立联系，不额外重复打招呼。
- 同一雇主/集团或品牌别名、相近职责、地点与团队：标为疑似同一实际空缺，人工核验。
- 不同链接、招聘人、标题或薪资不能证明是独立编制；同一实际空缺也可能跨平台出现。
- 雇主不明、信息缺失或上次点击结果未知时，先停止处理该问题。

`dedupe` 只能做标准化键匹配和保守疑点提示，不具备语义识别或空缺真实性核验能力。雇主别名需人工统一为同一个 `employer_key`，岗位类型需自行归类到 `role_family`。

## 6. 确认本次范围与发送动作，再由本人操作

发送前单独确认：本次岗位范围、最多联系数量、允许的动作（只匹配 / 首次沟通 / 另行发送指定附件）及遇到问题如何停止。数量不默认继承旧批次，不把登录或更新授权用于开聊，不将「直接匹配」误认为无限量投递。

用户选择只匹配时，到展示岗位建议与依据为止；不会点沟通按钮。要发送附件，还须确认具体接收对象、附件版本与文件名；沟通授权不自动覆盖附件发送。

本次范围、数量和动作已明确确认后，不因每个岗位都在同一范围内而反复索取同一授权；新增动作、扩大范围或改动硬条件时才重新确认。单纯平台简历版本不同，不等于首次沟通授权失效。

打开当前岗位详情，核对雇主、职责、地点、招聘方及按钮归属，再自行使用当前页面提供的沟通入口。点击可能立即对外发送招呼，不能把它当成只读查看。

如果平台已发送自动招呼，不机械补发相同消息；需要额外介绍时由本人确认内容再发送。附件简历必须独立确认接收对象、版本和可见发送结果，不自动附带发送。

本项目不推荐批量发送或固定安全频率。历史个案的等待秒数、批次数量和授权不能变成通用设置；即使拉长间隔也不代表符合平台规则或不会受到限制。

## 7. 分别核验、记录与暂停

| 事件 | 记录依据 | 不能推断 |
| --- | --- | --- |
| 在线资料保存 | 当前页面保存与读回状态 | 审核通过、已投递 |
| 首次沟通 | 同一岗位对应的可见招呼/聊天记录 | 附件已送达、已读、回复 |
| 附件发送 | 同一接收对象的附件名称、版本及可见发送状态 | 对方已查看或接受 |
| 招聘方回复 | 真实回复记录 | 面试邀请或录用 |
| 面试安排 | 双方确认的具体安排 | 录用结果 |

遇到超时、空响应或不确定结果，不重复点击试探。先查看当前会话和原记录；无法确定时记为 `pending_verification` 并停止后续沟通处理。出现验证码、限制或登录异常，不绕过、不自动重试。

每步说明已完成、待确认和下一步；可在 [会话进度表](../templates/session-plan.md) 记录。暂停或退出不清空待核实事项，恢复时重新核对账号、版本和本次范围；旧批次授权不自动续用。用户更换简历版本后重新确认受影响的更新与发送选择。

## 8. 台账与统计约定

`applications.csv` 每行代表一个岗位记录，`record_id` 唯一；所有身份字段仅保存在 `private/`。

- `job_key` 是当前平台的岗位标识；跨平台相同字符串不视为同一岗位。
- `employer_key`、`recruiter_key` 使用私有的统一键；未知字段留空，工具会提示去重信息不足。
- `status` 可选：`shortlisted`、`reviewed`、`greeting_verified`、`resume_sent_verified`、`replied`、`interviewing`、`offer`、`rejected`、`closed`、`pending_verification`、`skipped`。
- 确认事件分别填写带时区的 ISO 8601 时间，例如 `2026-01-02T10:00:00+08:00`，并在 `evidence_ref` 引用私有核验记录；不填写臆测的时间。
- 状态变化不抹掉历史事件时间；拒绝或关闭也不能从去重历史中消失。
- `summary` 只统计人工填有时间的事件，不把「已沟通」自动计为「附件已投递」。

推荐每周复盘匹配质量、回复、面试和待核实事项。不要只追求点击数量，也不要因没有回复自动重复联系。
