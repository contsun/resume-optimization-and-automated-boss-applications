# 隐私边界与发布步骤

## 不从私人项目直接删改后公开

本项目采用重新编写的通用内容、空白模板和全虚构例子，不复制真实简历再替换姓名。原始材料不移动、不删除、不覆盖；不搬运原仓库 `.git/`、版本归档或附件。

## 需要移除的内容

| 类别 | 不能进入公开仓库的内容 |
| --- | --- |
| 直接身份 | 姓名、照片、电话、真实邮箱、住址、证件、生日、社交账号、二维码 |
| 可重识别履历 | 真实雇主/品牌、学校、精准时间线、少见职称、项目组合及独特业绩数字 |
| 商业与第三方 | 客户名单、合同、内部系统、经营数据、招聘方姓名/联系方式、聊天、面试内容 |
| 账号与会话 | Cookie、令牌、浏览器状态、机器人配置、会话标识、认证文件 |
| 机器环境 | 绝对本机路径、用户名、进程/窗口/标签页、调度配置、通知回执 |
| 隐藏载体 | HTML 注释、文档属性、批注修订、图片文字/EXIF、旧版本、Git 历史和 CI 日志 |

泛化一个字段不代表匿名。真实雇主、职位、年份与数字的组合仍可能定位到个人。公司材料与招聘方信息也不属于可以随意公开的个人作品。

## 公开与私有分离

- `templates/`：空白结构，不填写自己的真实信息。
- `examples/`：明确标注的虚构案例，不是匿名化的真实经历。
- `private/`：实际求职资料、配置、事实底稿、附件及台账，不导出。
- `exports/`：候选公开包，不进 Git；分享前仍需检查包内容。
- `config/public-files.json`：精确公开白名单，不使用整个目录通配符。

`.gitignore` 不能清除已提交的资料；禁止直接公开带有历史个人数据的仓库。

## 自动检查能做什么

`python3 scripts/release.py` 检查白名单和未知文件、符号链接、非 UTF-8 文件、常见联系方式、绝对用户路径、真实岗位链接、平台身份标识和凭证特征。有本项目 Git 仓库且本机可用 Git 时，还检查索引中的文件名与内容；不检查历史提交。

输出只含规则与位置，不回显敏感值。错误码：0 表示本轮检查通过，1 表示检查失败，2 表示调用或配置错误。白名单文件、扫描器、测试及 CI 本身也在检查范围内。

可使用仅保存在私有位置的 JSON 字符串数组补充真实姓名、雇主、别名和独特项目标识：

```sh
python3 scripts/release.py --denylist private/private-denylist.json
```

拒绝词表不要加入白名单，也不要贴到 Issue。自动检查无法可靠识别所有自然人姓名、语义重识别、经过编码的秘密或文档中的商业机密；通过不等于「没有任何隐私」。

## 安全导出与首次发布

1. MIT 许可方式已于 2026-11-09 经项目持有人确认；首次公开前仍由本人核对公开文件、虚构示例和第三方材料权利，以及许可署名与覆盖范围。
2. 执行单元测试与隐私检查，人工复核补充拒绝词的匹配结果。
3. 用 `--export exports/resume-optimization-and-automated-boss-applications-0.2.0.zip` 导出；工具仅打包本次读入并通过扫描的白名单字节，不复制整个工作区。
4. 检查压缩包清单与内容，确认没有私人资料、账户状态、日志或旧 Git 数据。
5. 将包解压到全新空目录；确认当前 Git 作者信息及邮箱公开范围，避免无意暴露身份。
6. 在实际发布前由权利人确认仓库名、账号/组织、公开可见性及 MIT 许可所覆盖的公开内容；许可方式的确认不代替发布授权。
7. 获确认后再初始化新仓库、提交和发布；检查远端文件、提交历史、README、CI 日志、Issue 模板与 release 附件。

本地工具不执行第 5～7 步，不修改 Git 身份、账号或权限，也不推送远端。若旧仓库已经泄露，停止分享并按 `SECURITY.md` 处理；本项目不自动删除历史或撤销凭证。
