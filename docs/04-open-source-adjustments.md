# 从个人求职资料到公共项目：调整与路线图

## 已完成的公共工程

| 调整 | 当前实现 |
| --- | --- |
| 项目定位 | 通用简历优化与人工求职工作流，不使用真实人物命名 |
| 数据替换 | 不复制真实简历、附件、截图、聊天与历史批次；案例完全虚构 |
| 个人偏好解耦 | 岗位、城市、薪资、学历限制及排除规则由使用者在私有配置填写 |
| 环境解耦 | Python 标准库、跨平台相对路径、无需原作者的浏览器或会话 |
| 发送边界 | 将调度、数量、去重和遇错停止抽成通用模块；不迁移个人账号、历史授权、私人路径或现有任务安装 |
| 用户路线 | 有简历先选优化或直接匹配；无简历从述职/项目摘要或口述生成，三路汇合 |
| 投递前选择 | 先提醒本人电脑浏览器登录；在线/附件分别选是否更新；修改和发送独立确认 |
| 条件采集 | 专门询问岗位、城市、薪资范围与匹配口径，区分硬条件、优先项和本次沟通数量 |
| 默认投递口径 | 仅首次招呼，不发附件；版本差异轻提示并交用户决定，不强制一致或默认阻断 |
| 过程可见 | 人工会话进度表、虚构对话及可执行的授权、批次状态与私有事件台账；不冒充在线验收已通过 |
| 方法沉淀 | 事实底稿、指标口径、成果表达、岗位适配、版本核验和投递复盘 |
| 结果诚实 | 首次招呼、附件、回复和面试独立记录；未知与疑似重复不当作成功 |
| 基础工程 | 初始化、离线去重、分项统计、可配置调度、Chrome 可见页面适配、隐私扫描、白名单导出及回归测试 |
| 协作入口 | README、MIT 许可（方式已确认）、贡献指南、安全说明与最小权限 CI 配置 |

## P1：先验证最短用户路径

1. 邀请自愿测试者仅使用虚构数据，分别走通「原稿直接匹配」「优化后匹配」「无简历生成」，再测试拒绝更新、只匹配、暂停恢复和版本冲突；不要求先会用命令行。
2. 增加通用岗位案例；保留完全虚构标识，不收集真实履历建立样本库。
3. 增加本地 Markdown → HTML/PDF 导出与可读性检查，不上传简历到远端服务。
4. 改进台账字段说明、雇主别名归一与疑似同空缺人工审阅；不以文本相似度冒充独立空缺证明。
5. 增加 Windows 与最低 Python 版本实机验证；当前本地测试不等于所有平台已验证。
6. 0.2.0 已实现可配置调度、配置绑定授权、独占执行、历史去重、一次点击与回执核验。下一步须在用户明确授权且符合平台边界的前提下验收新 Chrome 适配器；当前仅通过虚构与协议测试，不等于现行平台已验收。

## P2：有明确需求再做

- 可选本地模型适配、逐字段脱敏和输入预览；外部模型适配须明确数据流、同意机制与退出方式。
- 多语言、无障碍模板和更多招聘平台的人工核验教程。
- 可选加密私有存储和本地事件审计，不引入默认遥测或公开求职档案。

不把自动海投、群发、验证码处理、账号共享、保证回复率或规避风控列为路线图。
