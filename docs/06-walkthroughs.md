# 从开始到投递：三条路线的对话示例

以下全部为虚构教学对话，不代表发生过真实登录、修改或发送。平台动作由本人完成；普通聊天和本项目的离线脚本不会因为读到这些提示词就获得浏览器控制能力。

## 示例一：已有简历，不优化，直接匹配

**用户**：这是我的简历，想找工作。

**助手**：这份材料可以读取。请先确认这是本次要用的版本。您想先优化，还是保留原文直接匹配岗位？也可以暂时只分析。

**用户**：用这个版本，不优化，直接匹配。

**助手**：会保留原文。请先告诉我想投哪些岗位、哪些城市，以及薪资最低要求和期望范围是月薪还是年包。再按需补充行业、排除公司、工作方式、不可放宽条件和本次最多沟通数量。已经说清的读回确认，不重复问；有目标 JD 可以一起提供。

**用户**：条件确认后，我想在 BOSS 上沟通。

**助手**：请您本人在自己的电脑浏览器打开 BOSS 直聘并登录，完成后告诉我。不要发送密码、验证码或 Cookie。现在不会修改简历或投递。

**用户**：我已登录，也确认是自己的账号。

**助手**：当前没有浏览器代操作能力，后续仍由您操作。在线简历和附件简历要如何处理：只更新在线、只更新附件、都更新，还是都不更新？

**用户**：都不更新。

**助手**：会保持不变。即使平台与参考简历不同，也只提醒一次，不要求一致才能继续。此次默认只点「立即沟通」并核验首次招呼，不发送附件文件；是否更新仍由您决定。

**用户**：保留现状，先按刚才确认的条件联系两个匹配且去重通过的岗位，不发附件。

**助手**：本次范围是最多两个岗位的首次沟通，不包含附件发送。先核对岗位与历史记录，再由您操作；出现未知回执或疑似同一实际空缺先停止。完成后只记录实际可见结果。

## 示例二：已有简历，先优化再投递

**用户**：先优化这份简历。

**助手**：先整理现有信息和缺口。若方便，可补充获授权的年终述职摘要、项目复盘或作品说明；没有也可以口述。先确认最影响改写的几个问题，不需要重填全部经历。

**用户**：我有一份可以分享的述职摘要。

**助手**：会区分公司成果、团队成果与您的个人贡献；待核实的数字不直接写成已证明事实。随后提供草稿、修改说明和待确认项。

**用户**：我确认修改后的版本，接下来想找岗位。

**助手**：先确认求职条件。您本人在电脑浏览器登录 BOSS 并确认账号后，再选择在线/附件是否更新；确认草稿不等于同意上传。

**用户**：两者都更新。

**助手**：先列出在线拟改字段与差异、附件文件名和版本，等您确认后分别操作和读回；不要顺带修改未授权设置，也不上传述职原件。更新完成后再单独确认本次岗位范围、数量及是否发送附件。

## 示例三：没有简历，从材料生成

**用户**：我没有简历，希望帮我做一份。

**助手**：可以先说最近的工作/项目、自己负责的部分和希望找的方向。如果有获授权的年终述职、季度总结、项目介绍或复盘摘要，也可以提供；没有材料不影响访谈开始。

**用户**：没有现成材料，我先口述。

**助手**：每轮补问少量关键问题，整理时间线、角色、个人动作、真实结果和教育信息；没有可信数字时写定性结果，不编造。先生成初稿，再按优化路线完善。

**用户**：这份稿件事实和版本我确认了，也想投递。

**助手**：确认求职条件后，仍需您本人在电脑浏览器登录，之后分别选择在线与附件是否更新；没有旧简历不意味着默认允许创建平台资料或上传文件。

**用户**：先只更新在线简历，不上传附件。

**助手**：只预览并确认在线字段修改，附件保持原状。完成核验后再确认本次允许的沟通范围，附件发送仍不在授权内。

## 常见分支不能省略

| 用户选择或遇到的情况 | 正确的下一步 |
| --- | --- |
| 只更新附件 | 确认目标文件、版本及替换范围；在线正文保持不变 |
| 只看岗位 | 提供匹配依据，不点沟通、不发附件 |
| 暂不登录 | 停在平台准备，可继续离线讨论条件 |
| 助手无法读取页面或文件 | 明确能力限制，改由本人操作或提供必要文字，不假装已核验 |
| 没有述职或项目材料 | 继续口述访谈，不堵住生成路线 |
| 简历仅版本不同或尚未核对 | 轻提示一次，由用户自选更新或保留；不阻断已确认的首次沟通 |
| 更新失败或实际文件发送不明确 | 报告实际状态；首次沟通不以更新成功为默认前提，另行发文件须确认对象和文件 |
| 暂停、换简历或恢复会话 | 保留待核实记录，重新确认受影响版本与本次范围，不复用旧发送许可 |

所有路线在结束或暂停时都读回：「已完成什么、还差什么、下一步需要您选择什么」。
